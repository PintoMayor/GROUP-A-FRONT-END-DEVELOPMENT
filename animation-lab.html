The CivicPulse motion system

Every animation on this page is made with the same three things: CSS keyframes, CSS transitions and JavaScript that adds and removes class names. No animation library. No SVG. No canvas. Just the stuff we have done in class.

How every animation here works

The same pattern is used on every page

  1. CSS hides the element first. If an element has data-reveal on it, the css gives it opacity: 0 and moves it down a bit with transform: translateY(...).
  2. JavaScript listens for scrolling. On every scroll we use getBoundingClientRect() to find out how far down the page each element is.
  3. When the element gets close to the screen we add one class: el.classList.add("is-visible").
  4. Then css does the animating. The .is-visible class sets opacity: 1 and moves the element back, and the transition on the element makes it slide smoothly.

That is the whole idea. JavaScript does not animate anything by itself, it only adds and removes class names and the browser does the rest. It is all plain DOM manipulation, which is what the whole project is built on.

Accessibility & performance notes

  • · Reduced motion — if the visitor has asked for less motion in their device settings, every effect stops.
  • · It still works without JavaScript — the content is only hidden once the script says it can show it again, so nothing gets stuck invisible.
  • · Only two scroll listeners — one for the reveals and one for the numbers, so scrolling stays smooth.
  • · Works on phones — the tilt, magnetic and glow effects are turned off on touch screens so the site stays quick and normal to use.
  • · Easy on the computer — we only animate transform and opacity, which the browser can do without slowing down the page.
